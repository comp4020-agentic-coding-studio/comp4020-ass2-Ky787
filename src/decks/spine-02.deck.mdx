## Three things reduce obfuscated arithmetic

1. **The algebra** — a simpler equivalent exists, and a solver can prove it
2. **The compiler backend** — instruction selection recognises an addition
3. **You** — by reading, which leaves no artefact anyone can check

Only one of these produces evidence.

---

## Nine operations for one addition

```llvm
%6  = xor i32 %5, -1          ; ~(x ^ 0x01010101)
%7  = mul i32 42, %6
%8  = add i32 -1128481603, %7
%9  = mul i32 1, %4
%10 = add i32 %8, %9
%11 = add i32 %10, 1145324680
%12 = add i32 %11, -68
%15 = mul i32 -42, %14        ; %14 == %6
%16 = add i32 %12, %15
```

---

## …is an addition

`%7` and `%15` cancel: `42·A − 42·A = 0`

```text
−1128481603 + 1145324680 − 68  =  16843009  =  0x01010101
```

Everything else is `1 · x`.

```notes
- have the room do the constant fold. It takes 40 seconds and it lands
- note shl edx, 0x0 in the machine code: multiply by one, lowered, not removed
```

The deciding variable is *where it was applied*.

## What a simplifier claims

Three expressions, two obligations:

- **input** — lifted from the machine code
- **candidate** — what the tool proposes
- **expected** — the known original (only in a study)

```text
input ≢ candidate   →  is it sound?
candidate ≢ expected →  did it recover?
```
